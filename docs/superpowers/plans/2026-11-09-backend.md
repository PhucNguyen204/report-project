# Backend Đi chợ tiện lợi — Implementation Plan

> **For agentic workers:** thực hiện theo từng tính năng, TDD và verification-before-completion. Người dùng đã yêu cầu triển khai ngay và sử dụng sub-agent; không cần vòng hỏi lại lựa chọn triển khai.

**Goal:** triển khai backend theo 25 use case đã chốt, có kiểm thử tự động, commit theo tính năng và một báo cáo tiến độ chung.

**Architecture:** modular monolith Go, PostgreSQL là nguồn dữ liệu chính. HTTP chỉ giải mã/kiểm tra đầu vào và ánh xạ lỗi; dịch vụ sở hữu nghiệp vụ và giao dịch; các module giao tiếp qua interface. API và worker dùng chung logic ứng dụng.

**Tech Stack:** Go đang được hỗ trợ (máy hiện tại: 1.26.6), net/http, pgx v5, PostgreSQL 16, Argon2id, Ed25519 JWT; Docker Compose cho môi trường kiểm thử. Thêm Redis/S3/FCM qua adapter, có fake ở biên để test tất định. PostgreSQL pg_trgm đáp ứng tìm kiếm bản đầu.

**Spec:** [AGENTS.md](../../../AGENTS.md), [chương 1](../../../chapters/chuong1.tex), [use case](../../../chapters/c2), [thiết kế backend](../../../chapters/c3), [API chi tiết](../../../backmatter/pl/f-dac-ta-api.tex), [bảng dữ liệu](../../../backmatter/pl/g-dac-ta-bang.tex).

Đã clone [obra/superpowers](https://github.com/obra/superpowers) tại commit `22f0b463e7a5e579904dd6211a520321035526f7`; cài `writing-plans`, `test-driven-development`, `verification-before-completion` vào `~/.codex/skills/`. Mỗi tính năng đi theo vòng: test mô tả hành vi → chạy và quan sát thất bại đúng nguyên nhân → code tối thiểu → chạy test → refactor → chạy kiểm tra liên quan và regression suite → review diff → cập nhật báo cáo → commit. Không dùng tỷ lệ coverage để thay thế assertion nghiệp vụ.

Sub-agent nhận quyền sở hữu file/module rõ ràng. Root giữ shared contracts, router, migrations runner, CI, tích hợp và Git commit để tránh tranh index. Module giao tiếp bằng các interface bên dưới; thay đổi hợp đồng phải báo root trước.

## 4. Cấu trúc file và hợp đồng module

```text
backend/
  cmd/server/main.go              cấu hình, nối dependency, graceful shutdown
  internal/platform/             DB, TxManager, HTTP envelope/auth context, clock
  internal/kernel/               Quantity, Money, lỗi có kiểu
  internal/modules/accounts/     identity, household, catalog, config/admin
  internal/modules/inventory/    pantry và shopping
  internal/modules/planning/     recipe, mealplan, search, report
  internal/modules/notification/ inbox, worker, delivery adapter
  internal/modules/media/        upload, kiểm tra đối tượng, signed URL
  migrations/                    SQL versioned, thứ tự dependency
  api/openapi.json                hợp đồng được kiểm tra bằng test
  tests/integration/             API + DB thật, concurrency, rollback
  compose.yaml                   PostgreSQL test/dev, dịch vụ tùy chọn
  Makefile                       verify, test, coverage, integration, smoke
```

Ba cụm module trên là ranh giới phân công ban đầu; mỗi nghiệp vụ có file service/handler/repository và schema riêng. Không ép tạo đủ thư mục rỗng trước khi có tính năng.

Hợp đồng chung được root tạo trước, dùng module `dicho`:

```go
type Principal struct { UserID, SessionID, SystemRole string }
type Clock interface { Now() time.Time }
type DB struct { Pool *pgxpool.Pool; Clock Clock }
func (db *DB) Tx(ctx context.Context, fn func(pgx.Tx) error) error
func Current(r *http.Request) Principal
func (db *DB) RequireMember(ctx context.Context, q Querier, spaceID, userID string) (string, error)
func Write(w http.ResponseWriter, status int, data any)
func Fail(w http.ResponseWriter, err error)
type StockPort interface {
    Available(ctx context.Context, tx pgx.Tx, spaceID string, on time.Time) ([]Stock, error)
    Consume(ctx context.Context, tx pgx.Tx, spaceID, mealID string, lines []Consumption) error
}
```

Hợp đồng trong code `backend/internal/platform/contracts.go` là nguồn chuẩn cho tên/kiểu; root chốt trước khi agent triển khai. Internal activity/change_seq vẫn phải có dù Y01/Y02 bị hoãn. Các DTO Stock/Consumption đặt trong `internal/platform/contracts.go`, lượng là kiểu Quantity. Adapter inventory hiện thực StockPort; planning không ghi bảng pantry trực tiếp. Accounts cung cấp middleware authentication và RequireMember dựa PostgreSQL; root nối router sau khi từng cụm có test độc lập. Migrations dùng tên số không trùng: platform 001, accounts 010–019, inventory 020–029, planning 030–039, notification/media 040–049.

## 6. Checklist thao tác cho từng tính năng

Mỗi dòng Fxx khi bắt đầu được mở thành entry trong báo cáo chung, với đúng UC/API/BR và test của dòng đó.

- [ ] Chốt input/output, invariant, người sở hữu file và interface sử dụng; đọc đặc tả liên quan.
- [ ] Viết test hành vi thất bại; ví dụ `TestStockItems_RollsBackEntireBatch`, không chỉ mock call count.
- [ ] Chạy test mới bằng `go test <package> -run <test-name> -count=1 -v`; lưu RED đúng nguyên nhân.
- [ ] Code service/SQL/handler tối thiểu theo ranh giới đã chốt; thêm migration cùng tính năng.
- [ ] Chạy lại cùng lệnh, yêu cầu GREEN; thêm trường hợp lỗi/biên/quyền/đồng thời theo ma trận.
- [ ] Chạy `make verify` và `make integration`; kiểm tra output/exit code, không đánh PASS khi test bị skip.
- [ ] Review diff, cập nhật checklist và kết quả/giới hạn trong `docs/backend/PROGRESS.md`.
- [ ] Commit file của tính năng + test + migration + báo cáo, message `feat(<module>): <behavior>` và trailer `Feature-ID: Fxx`.
- [ ] Ghi SHA và CI run vào entry ở lần cập nhật tiếp theo; dòng hiện tại truy bằng trailer, tránh vòng tự tham chiếu SHA.

## 7. Thiết kế kiểm thử

| Lớp | Thực thi | Assertion chính |
|---|---|---|
| Unit/domain | `go test ./... -count=1` | Hàm thuần, boundary, validation, state machine, Quantity/FEFO/BR20/score |
| HTTP/contract | httptest với router thật | Auth/envelope/status, malformed JSON, size limit, field errors, route thực sự đăng ký |
| Integration | PostgreSQL16 thật, DB/schema riêng mỗi suite | Constraint, transaction, advisory/row lock, idempotency, SQL query scope, migration |
| Concurrency | Hai connection, barrier điều phối | Tranh chỗ cuối, purchase/stock/cook, revoke/member removal; không dùng sleep làm đồng bộ |
| Worker | Store thật + clock và provider fake | Transactional enqueue, dedupe, retry/per-device, lịch chạy bù, cancellation |
| E2E | API chạy thật, DB/worker thật | K1–K5 liên tiếp qua HTTP; số liệu và state kiểm tra từ API/DB |
| External smoke | Adapter thật ở staging khi có credential | Email, FCM, signed S3 URL upload/download; fake test không thay được smoke này |
| Security | Regression auth + scanner | Cross-space/IDOR, admin, token replay, brute force, SQL injection, media ownership, secrets |
| Performance | Load script với fixture được lưu | p95 API≤1s; suggest≤2s với500 recipes/200lots; suggest name≤500ms; ghi môi trường/concurrency/error rate |
| Recovery | Backup/restore DB mới | Kiểm tra hàng/movement/report sau restore; retry worker không sinh hiệu ứng nghiệp vụ trùng |

Coverage: baseline báo cáo NFR20 là nghiệp vụ≥70%; mục tiêu dự án nâng lên≥85% cho handwritten domain/application, ≥90% cho Quantity/FEFO/BR20/scoring. Không loại code khó test khỏi denominator; generated files được tách công khai. Kiểm đủ case quan trọng dù đạt tỷ lệ; không tuyên bố 100% correctness.

Fuzz tập trung JSON/Quantity/date range và invariants FEFO (không âm, tổng trừ đúng, không dùng supply hai lần). Race detector chạy cùng toàn unit/integration suite; `-race` không thay test transaction PostgreSQL.

Chính sách số: Quantity fixed-point6 chữ số, factor đơn vị4 chữ số; phép cộng/gộp phải bảo toàn lượng, dùng đơn vị cơ sở nếu cần, và từ chối khi vẫn không biểu diễn được theo precision API. Tiền VND làm tròn half-up tại ranh giới tính tiền; intermediate dùng số nguyên rộng/math big và kiểm overflow.

Nghiệm thu vận hành: reminder≥99% tạo trong15 phút; backup hằng ngày giữ7 bản, RPO≤5 phút/RTO≤1 giờ; availability≥99% trong06:00–23:00 chỉ được xác nhận bằng monitoring đủ kỳ. Chạy một bài test không chứng minh availability.

## 8. Definition of Done và release gate

- [ ] UC/API/BR liên quan được truy vết tới case và kết quả, bao gồm biến thể A/B/C.
- [ ] Business logic độc lập transport; không chu trình package, không ghi chéo schema; report chỉ đọc qua view.
- [ ] Không float cho lượng/tiền, không truy vấn tenant thiếu scope, không secret/token/password trong log.
- [ ] Authz được kiểm lại ở transaction cần khóa; logout/revoke có hiệu lực với access token hiện có.
- [ ] Không gọi email/FCM/S3 trong transaction DB; persist job cùng tx và adapter có timeout/cancel.
- [ ] Unit/contract/integration/race/regression pass; các test liên quan lỗi/biên/quyền đều tồn tại và có assertion thật.
- [ ] Migration từ rỗng và nâng phiên bản chạy được; reset chỉ dành DB test; dữ liệu thật theo expand-contract.
- [ ] OpenAPI route/request/response khớp implementation; không endpoint placeholder trả thành công.
- [ ] Format/vet/lint/build pass; dependency/secret scan không có High/Critical chưa xử lý; không tăng scope chỉ để qua gate.
- [ ] Báo cáo ghi lệnh, số case pass/fail/skip, coverage, artifact/CI URL, lỗi còn mở và commit.
- [ ] Comment ngắn theo vai trò function; không code chết, TODO đánh tráo tính năng, test-only branch trong production.
- [ ] Chốt release chỉ sau K1–K5, smoke dịch vụ thật và restore; credential chưa có phải nêu rõ là chưa kiểm chứng.

Các mục NFR phía giao diện/thiết bị (font, tap count, Keystore/Keychain, Android/iOS, local DB) giao cho client; backend cung cấp hợp đồng và hỗ trợ kiểm thử nhưng không tự tick thay frontend.

## 10. Tài liệu chính thức dùng khi chốt toolchain

Go hỗ trợ mỗi major tới khi có hai major mới hơn; pin bản còn hỗ trợ và kiểm tra `go.mod`/CI cùng version. [Go release policy](https://go.dev/doc/devel/release).

OpenAPI3.1/codegen cần kiểm chứng trên schema thật và pin cả generator/runtime tương thích; không tự đổi schema version để che lỗi sinh mã. [oapi-codegen releases](https://github.com/oapi-codegen/oapi-codegen/releases).

Job nghiệp vụ phải được enqueue trong transaction thay vì commit rồi mới gửi queue. Nếu chọn River khi triển khai adapter thì dùng InsertTx và kiểm thử rollback thật. [River transactional enqueueing](https://riverqueue.com/docs/transactional-enqueueing).
